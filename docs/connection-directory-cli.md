# 接続一覧CLIの導入

運営支援付きの社内試験向け。利用者はDBやSSHを扱わない。

## 配布

1. CIで`npm ci && npm run check`が通ったコミットから`npm pack`相当の配布物を作る。
2. 配布アーカイブのコミット、版、SHA-256を運営記録に残す。
3. 利用者のmacOSアカウントへ、運営立ち会いでCLIと一覧専用資格情報を配置する。
4. 既定の資格情報パスは`~/.config/anybots/directory.json`（親0700、ファイル0600）。

自動更新や`curl | sh`は使わない。利用者へリポジトリのcloneや依存解決を求めない。

## 初回確認

```sh
anybots connections
anybots connections --connection <自分の接続UUID>
anybots connections --json
```

登録控えの接続UUIDと表示が一致することを確認する。同じサービスの複数接続はUUIDで区別する。

## 失敗時

| 終了コード | 意味 | 次の行動 |
| --- | --- | --- |
| 2 | 引数または資格情報ファイルの問題 | パスと権限を確認し、運営へ再配置を依頼 |
| 3 | 401/403 | 運営へ再発行または閲覧権限確認を依頼 |
| 4 | 400/404/422 | 登録控えのUUIDを確認。上限超過なら運営へ相談 |
| 5 | 429/503・通信・応答検査失敗 | しばらくして再実行。続く場合は運営へ連絡 |

秘密、生のHTTP本文、例外は表示しない。自動再試行はしない。

## 再発行

期限切れや漏えい時は運営が資格情報IDを失効させ、本人確認のうえ再発行する。利用者は同じ`anybots connections`コマンドで確認する。
